# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A local-only app that turns a long video into a short highlight. Flask + Socket.IO backend (`app/`), React + Vite frontend (`frontend/`), FFmpeg for all media work, faster-whisper for speech, and Ollama (vision + text models) for scoring. No cloud AI: the only network calls go to the configured Ollama URL(s). The one opt-in exception is a narrated video whose brief the user chose to have written by Claude (Claude Code CLI on the user's subscription, see "Narrated videos"); model and tool downloads happen only from their Settings buttons.

The user runs the app natively on Windows (CPU-only, ~16 GB RAM, Ollama installed on the host). Docker/Compose files exist but are not the user's current setup.

## Architecture

**Request → job → worker.** Routes (`app/routes/`) only create and inspect jobs. `JobManager` (`app/services/job_manager.py`) stores jobs in SQLite (`data/app.db`) and files under `data/jobs/<id>/`. A single daemon thread (`app/workers/worker.py`) polls for `queued` jobs and runs either analysis or render. Progress and logs go out over Socket.IO (`job_progress`, `job_log`, …) and are appended to `job.log`. Jobs left mid-run are re-queued at startup; their attempt time counts up to the last heartbeat (`attempt_seen_at`, written every 15 s), and an interrupted analysis waits up to 3 minutes for Ollama (`_wait_for_ollama`) before falling back.

**Pause, crashes and power cuts.** `POST /jobs/<id>/pause` stops a run like a cancel (via the same cancel event), but the worker ends it as `paused` (`JobManager.take_pause_request`); paused jobs are never re-queued at startup, and `resume` re-queues them like `retry`. Every persistent JSON write goes through `app/utils/atomic.py` (temp file + fsync + rename); media is written under a temporary name (`part_path`, or `encoding/` for render clips) and renamed when complete. Slow steps save progress as they go and delete it when the step finishes: `transcript.partial.json` (Whisper resumes from the last saved segment), `segment_scores.partial.json` (keyed by a transcript fingerprint), `visual_analysis.partial.json` (keyed by the vision focus). Render clips are reused across runs when the fingerprint of their FFmpeg command (plus burned subtitle text) in `tmp_render/<label>/clips_done.json` still matches.

**Analysis pipeline** (`app/analysis/pipeline.py`, `VideoAnalyzer`): metadata → scenes (PySceneDetect) → audio → transcript (Whisper) → silence → frames (+ picture quality and loudness from `signals.py`, cached as `scene_quality.json` / `audio_energy.json`) → transcript AI → visual AI (only on `shortlist_scenes` unless `vision_scope=all`) → candidates (incl. sentence-complete joins, focus matching via `semantic.py`) → repetition removal (word-based, plus calibrated Ollama embeddings when `ollama_embed_model` is installed) → planning (`ClipOptimizer`). Transcript scoring must stay before visual analysis: it feeds the shortlist. Without speech (`enable_whisper` off, or `HighlightConfig.use_speech=False` from the Create page's "Visuals and sound only"), transcription and speech scoring are skipped without overwriting cached speech results, and the shortlist ranks scenes by a quick picture/motion/sound/quality signal. `app/analysis/image_match.py` adds optional SigLIP picture matching (ONNX, `Xenova/siglip-base-patch16-224`, full precision, downloaded from Settings; CPU by default, CUDA/DirectML when an onnxruntime GPU build is installed): it ranks scenes, marks lookalikes, matches the focus text to pictures, and improves quick scores for scenes the vision model skipped. It never overrides a vision-model score. `analyze_sources` handles one or many source videos. With several videos, each is analyzed in `job/work/<source id>/` and the candidates are merged before planning.

**Speed and reliability of the analysis.** Scenes and frames are read from `analysis_proxy.mp4` (`_analysis_proxy`: a 540p, ultrafast x264, `-fps_mode passthrough` copy, made when the short side is above 720 px or the codec is AV1/HEVC/VP9; deleted after planning, in `_CACHE_FILES`); every frame consumer downsizes to 512 px or less anyway. The vision shortlist is sized by `_highlight_seconds` (middle of the range, at most 40% of the video). `HighlightConfig.speech_language` (Create page) is passed to Whisper (a cached transcript in another language is redone via `_forget_speech`); `Transcript.language_probability` is stored. Whisper runs in faster-whisper's batched mode (`whisper_batch_size`, default 8; 0 = the old one-at-a-time method): pieces of up to 30 s between pauses, several at once, no temperature retries (measured 6.5x faster on CPU, and no repetition loops on poorly supported languages); `_sentence_segments` splits the pieces again after sentence ends and at pauses of 1 s or more using word times, because candidates are built from segments. Narration word alignment (`kokoro.align_words`) keeps the old method. `app/analysis/speech_check.py` marks a garbled transcript unreliable (mixed scripts, mixed-script words, repeated letters, wrong script for the language; typical of Whisper base on Malayalam/Tamil): transcript AI scoring is skipped, word timings are still used for cuts, and `content_index.json` gets `speech_reliable: false` so the AI editor and brief do not read the words. Before that, with `whisper_translate_unreliable` (default on) `_translate_speech` runs Whisper again with `task="translate"` (progress in `transcript_translation.partial.json`) and keeps the English text only if it passes the check: `Transcript.translated` is then true, `language` stays the spoken language (so a chosen language does not redo it), `speech_check` expects Latin text, and `_forget_words` drops segment scores and voices read from the old segments. A cached unreliable transcript is translated on the next analysis; an unreadable translation sets `translation_unreadable` so it is not tried again, while a failed one is retried. `generate_candidates` keeps up to 25% of its cap for the best moment of every 60 s that would otherwise have none (`keep_with_coverage`). Each candidate stores `cuts` ([time, strength] from `boundaries.CutPoints`: sentence ends, pauses, silences, scene starts); `fit_candidate`/`keep_best_span` shorten a moment only between cut points (falling back to the old time-based cut), and spoken moments in auto clip length are at least `SPEECH_MIN` (2.5 s). Splitting the video for parallel processing was evaluated and not done: on a CPU, Ollama and Whisper already use every core. Running the analysis copy and Whisper side by side was measured on a 6-core 15 W laptop CPU: 12% of their combined time saved (69.6 s → 61.6 s for 2 minutes of 4K AV1), about a minute per 17-minute video, so the pipeline stays sequential. Moving the vision instructions into a system message was also measured: Ollama's image-model runner re-reads the whole prompt every request (identical prompt_eval_count), so it would change the model's input for no gain. Vision scenes can be tiled into labelled grids (`app/analysis/frame_grid.py`, `ollama_vision_scenes_per_image`, default 1 = off, at most 9): Ollama reads any picture up to about a megapixel at the same ~1,050 tokens, so a 2x2 grid of 512 px frames costs one frame (measured 34 s either way on CPU). It is off by default: on a real job (24 scenes, prompt mode) grids were 2.3x faster but changed the scores (importance rank correlation 0.48 with single frames, several 0.0/0.8 flips), while single-frame scoring at temperature 0.1 reproduced the saved scores exactly, so any vision prompt change can be checked against a job's `visual_analysis.json`. Replies are matched by the scene id in each tile's label; `fitting_scenes_per_image` puts fewer scenes in a picture when the replies would not fit the context (3 in prompt mode at 2048), a frame that cannot be opened is sent alone the old way, and `ollama_vision_batch_size` now counts pictures per request. Time estimates and recorded speeds stay per one-frame request (`vision_scene_cost`: 80% of a request is reading the picture).

The `Connection` priority guides visual scoring toward affectionate gestures and meaningful interaction; the topic priorities (`people`, `scenery`, `fun`, `pets`, `music`, `sports`) work the same way. Each has weights in `scorer.PRIORITY_EMPHASIS`, a vision-prompt hint (`prompts.PRIORITY_VISUAL_HINTS`) and a SigLIP picture description (`prompts.PRIORITY_PICTURE_TEXT`). Styles have weights in `scorer.STYLE_EMPHASIS`, newer ones a transcript-prompt hint, and clip pacing in `sequence_limits.desired_auto_length`. Where a style and the chosen priorities weight the same signal, each counts half; with `auto`/`custom` style the priority weights apply unchanged. Connection quick presets set a 30–60s highlight or 10–20s short-moment target, a soft fade, natural-sound ranking, and suitable per-clip limits; each remains editable. "What to leave out" (`HighlightConfig.avoid`, `avoid_custom`, `avoid_mode`) lives in `app/analysis/avoid.py`: detectors store `avoid_match` on each candidate (transcript phrases, silence, picture quality, SigLIP contrast margins calibrated on real footage, an optional vision-model `avoid` score, embeddings for the user's words); `apply` ranks matches lower or removes them at planning time and in `plan_from_cache`, falling back to ranking lower if everything would be removed. Choosing picture or custom items changes the vision prompt, so cached visual scores are redone. Audio focus changes candidate ranking using the cached loudness curve and transcript coverage, never replaces or filters source audio. Fade transitions apply a brief fade to both picture and sound.

**Prompt mode** (`HighlightConfig.mode="prompt"`, "Describe it" on the Create page; manual mode is unchanged). `app/ai/intent.py` turns the description into a settings patch plus `PromptRequirements` (keep / remove / moments / visual_cues / audio_cues): regex rules read lengths, times, shape, captions and shorts (they win over the model; a length that describes the source, such as "the original 17-minute video", or is at least 90% of the video's length is ignored, and "as short as possible" means automatic length with `auto_length_strict`; the model's `subtitles` choice is dropped unless the description mentions captions or subtitles), the text model reads the meaning (`INTENT_SCHEMA`), and every value is validated through `HighlightConfig` (`POST /api/prompt/interpret`, shown as an editable preview). Prompt-mode analysis adds: a `caption` per AI-scored scene (vision reply, `VISION_CAPTION_TOKENS`; AI scores without a caption are redone, AI scores are never overwritten by fallbacks), CLAP sound labels (`app/analysis/audio_events.py`, features in `clap_features.py` match HF's ClapFeatureExtractor; 5 s windows on a temporary 48 kHz copy; `sound_events.json` + `sound_vectors.npy`, so new wanted sounds re-match without re-reading audio; model downloaded from Settings via the shared `app/ai/onnx_models.HubModel`, like SigLIP), prompt-matching scenes added to the vision shortlist, `analysis_depth="best"` = every scene. `use_visuals` / `use_speech` are the per-job video/audio analysis switches (not both off). After repeat removal, `content_index.json` (captions + sounds per source) and the AI editor (`app/analysis/director.py`) pick candidates **by alias id only** (never times), with role and reason, in steps: an **outline** from chapter summaries (`build_chapters`, ~75 s each, at most 12; `OUTLINE_SCHEMA`: beats with chapter, role, purpose, seconds; first beat hook, last ending), **picks** per beat (moment lines carry their chapter; long videos are read in parts then a final pick), **shape** (`_shape`: empty beats get their chapter's best moment, outline order, `_fix_roles` = one hook first and one ending last) and an optional **review** (`director_review` setting, `REVIEW_SCHEMA`: remove repeats, add the moment just before one that needs it). The editor is the local model or Claude (`director_engine` setting, per-job `HighlightConfig.director_engine`, "" = setting): Claude reads everything in one request through `ClaudeCliEngine._ask`; its failures save `brief/failure.json` with `stage: "director"` and pause the job (`BriefPaused`), and `POST /jobs/<id>/brief-engine` switches the editor (not the brief) for such a pause. The plan (`VERSION` 2, with `outline`, `engine`, `review`) is cached in `director_plan.json` by a key of its inputs. `apply_director` makes picks a strong preference for `ClipOptimizer` (which still owns length, shorts, must-include/exclude, overlaps; picks skip the low-value/novelty filters; moments it did not pick are only used to reach the minimum length and are placed after the pick before them in the video, never before the hook or after the ending (`_story_order`); `order_mode="ai"` follows the editor's story order) and is applied in `plan_from_cache` too. "Ask AI to change" (`POST /jobs/<id>/refine`) appends to `refine_notes` and queues the job with `analysis_status="refining"`; the worker then runs `VideoAnalyzer.refine` (editor + planning from cache only). The editor uses role `"director"` in `role_options` (`ollama_director_num_ctx`, reloads the text model once) and optional `think` (`director_think`, retried without on errors). No Ollama: rules-only patch, the description becomes the focus, planning from scores.

**Narrated videos** (`HighlightConfig.video_brief`, `brief_engine`, `narration`; "Narrated video" on the Create page). After the AI editor, the `brief` stage (`VideoAnalyzer._brief`) writes `brief.json` with `app/brief/`: `evidence.build_pack` (the director's moment lines, aliases m1…; plus labelled frame sheets in `brief/sheets/` for Claude when `claude_send_frames`) → the engine the user chose → `validate.check` (unknown aliases, must-include/exclude, length, per-beat word budget `schema.word_budget` at `WORDS_PER_SECOND`) → one repair request → rules fix the rest. Engines: `engines/local.py` (director picks + small writer requests; rules without Ollama, never stops the job) and `engines/claude_cli.py` (`claude -p --restricted --tools "" --strict-mcp-config --no-session-persistence --input-format/--output-format stream-json --json-schema …`, cwd `job/brief/`, ANTHROPIC_API_KEY removed from its env so the subscription is used; any failure raises `BriefEngineError` → `BriefPaused` → the worker pauses the job with `brief/failure.json`; "Use the local engine" = `POST /jobs/<id>/brief-engine {resume}`. **Never switch engines automatically.**) `apply_brief` ranks the brief's moments like the director's picks, and `planning_config` plans in story order unless the user chose another order; `plan_from_cache` does the same. Render (`_run_render`): `compose.prepare_narration` speaks lines with `app/voice/kokoro.py` (model `fastrtc/kokoro-onnx` via `HubModel`, per-line cache `narration/<key>.wav` + `narration.json`, word timings by faster-whisper `match_words`) → `fit_clips` lengthens a narrated beat's last clip when its line needs more time → normal render (source-speech burned captions off when narrated) → `compose_video`: `render_spec.build_spec` (one timeline for preview, Remotion and FFmpeg; schema in `remotion/src/spec.schema.json`) → Remotion (`app/compose/remotion.py`: `remotion/scripts/render.mjs`, silent ~10 s chunks with `chunks_done.json` fingerprints, base video served from a 127.0.0.1 server) or FFmpeg ASS fallback (`spec_ass`) → `audio_mix.narration_mix_command` (per-line loudnorm, ducking) → music as before. Review: `BriefPanel` edits text (`PUT /jobs/<id>/brief`), speaks lines in the background (`services/narration_preview.py`), and plays `GET /jobs/<id>/preview-spec` with `@remotion/player` and the same `Reel` composition (frontend alias `@reel` → `../remotion/src`, deduped react/remotion/zod). Settings → Narrated videos: engine default, Claude model/effort/frames/timeout/budget, voice download/voice/speed, render engine and "Prepare video tools" (`npm ci`, bundle to `data/cache/remotion-bundle/<hash>`, `ensureBrowser`).

**Stage cache.** Each stage writes a JSON file in the job folder (`scenes.json`, `transcript.json`, `visual_analysis.json`, `segment_scores.json`, …) and `load_cache` feeds them back, so re-planning and retries skip finished stages. Changing the crop clears the cache. AI scores are tagged by `app/analysis/score_source.py`: fallback scores with a retryable reason are redone when the model is available again, and untagged entries from older versions are kept. Cached AI scores are **not** invalidated when the style, custom focus or model changes; visual scores are refreshed when the set of priorities with a vision-prompt hint changes (stored in `visual_connection_focus.json`; older `true`/`false` values mean Connection on/off).

**Degraded modes are a feature.** Every AI step has a deterministic fallback: motion scoring for frames, heuristics for transcript segments. Ollama being down, a model missing, a reply cut off or malformed must never fail the job. Keep that property when touching `visual.py` / `pipeline.py`.

**Ollama client** (`app/ai/ollama.py`, shared instance from `services/ollama_runtime.get_ollama_client`):
- `role_options(role)` gives `num_ctx` (+ `num_thread` only when Ollama runs on this machine). Warm-up, probes and real calls must share it, because Ollama reloads a model when these options change.
- Batched JSON replies use `predict_budget`. A reply that hits the limit raises `OllamaTruncatedError`, and callers split the batch in half and retry.
- Batches are sized to fit the context window: `plan_text_batches` (transcript, token estimate) and `fitting_vision_batch` (vision; about 1,100 prompt tokens per picture regardless of resolution, because Ollama upscales Qwen3-VL frames; each picture holds up to `ollama_vision_scenes_per_image` scenes).
- Connection fallback: Docker host aliases, plus optional `OLLAMA_FALLBACK_URL`. The client returns to the configured URL when it answers again (checked at most once a minute). Optional `OLLAMA_API_KEY` is sent as a Bearer token and is filtered out of `GET /api/settings`.
- `usage_snapshot()` keeps per-thread token and time totals. The pipeline logs them per stage, and logs stage timings at the end.

**Model choice.** `app/services/hardware.py` detects CPU (name, performance/efficiency cores, AVX), every graphics adapter (NVIDIA via `nvidia-smi`, AMD/Intel VRAM on Windows from the display-class registry, ROCm VRAM, built-in vs separate), battery, and whether Whisper can use CUDA (`ctranslate2`, not torch). An AMD/Intel card counts for inference only once Ollama was seen running a model on it (`gpu_confirmed` setting). `app/services/model_catalog.py` recommends models from VRAM/RAM/CPU and the goal `ai_goal` (`quality`/`balanced`/`fast`); RAM is compared as its label size (`nominal_ram_gb`: 15.8 GB counts as 16), and vision batch and context come from the shared `app/ai/context_fit.py` sums, so recommended values are what jobs actually use. `app/services/ai_profile.py` applies the recommendation in **auto** mode when the hardware fingerprint changes. Bump `RECOMMENDATION_VERSION` whenever recommendations change, so existing auto-mode installs pick them up once. Custom mode is never overwritten. In auto mode, a managed setting edited by hand is **pinned** (`ai_auto_pinned`) instead of turning auto off; a recommended Ollama model that is not installed is held (`hw_auto_held`) until it is downloaded; Ollama-host settings are left alone when Ollama is on another computer. `app/services/auto_tune.py` backs the Settings switch "Automatically optimize for my system": goal, pins, review of changes with reasons, undo snapshot (`auto_tune_previous`), and per-run speed history (`perf_history`) that only produces suggestions, never automatic changes. `app/services/calibration.py` ("Measure this computer", `perf_profile`) measures real model speed and turns it into time estimates and suggestions only. It manages exactly `ai_profile.APPLIED_FIELDS`, and other settings are never touched.

**Run plan.** `app/services/run_plan.py` decides per job, from live free memory and load, whether models are loaded one at a time (Whisper and SigLIP released after use, other Ollama models unloaded before visual AI with `keep_alive: 0`) and Whisper precision on small cards. Never saved, never swaps models. When a model runs out of memory, visual and transcript scoring free the other models and retry in halves, then fall back with the retryable `AI_FAILED` reason.

**Settings precedence.** `.env` / environment → `Settings` (`app/config.py`). Values saved from the UI go into the SQLite `settings` table and are overlaid by `effective_settings()`; only keys in `EDITABLE` (`app/routes/settings.py`) can be saved. Editing a managed key in auto mode pins it (see Model choice).

**Video** (`app/video/`): `VideoProcessor` builds FFmpeg argv lists (never shell strings; paths go through `safe_path_argument`). `FFmpegRunner` executes them, can run several at once (parallel frame extraction), and `cancel()` kills all of them. `Renderer` cuts and concatenates the clip plan, with optional subtitles, 9:16 output and hardware encoders. Each clip is cut on its own and starts at 0, so burned subtitles are written per clip (`captions.py`, plain SRT or styled ASS) through the `clip_subtitles` callback. `reframe.py` centres 9:16/1:1/4:5 crops on faces per clip.

**Render** (`_run_render` in `worker.py`): kept clips with their times exactly as saved on Review (no longest-clip clamp: the planner already fits planned clips, so a longer clip was made longer on purpose; clips with end ≤ start are skipped with a warning) → optional tighten (`analysis/tighten.py`, pieces marked `join_previous`) → `render_groups`: one `highlight.*`, or `short_NN.*` per short when `HighlightConfig.shorts_count` ≥ 2 (clips carry `short_index`, planned by `ClipOptimizer.select_shorts`). Output rows and stale files are replaced only after every video is made. Routes that serve output take `?short=N` (`services/outputs.py`). Per clip the renderer can add even loudness (`audio_mix.py`: measure, four clips at a time, then `volume` + `alimiter`; x264 uses preset `medium` for every quality) and picture extras (`overlays.py`: punch-in, logo via `movie=`, progress bar via `color` + `overlay`, all inside the clip's `-vf` graph). Background music is mixed into each finished video afterwards (`add_music` in `worker.py`); translated subtitles come from `services/translate.py`. `analysis/speakers.py` tells voices apart on demand (numpy MFCC + pitch voice prints, agglomerative clustering with silhouette and a separation check; cached in `speakers.json`, used by `plan_from_cache` when `focus_speaker` is set, filtered before repeat removal). `services/watch_folder.py` runs a polling thread (started with the worker) that creates `auto_render` jobs. The editor export (`services/editor_export.py`) uses the same clips and tightening so its timelines match the video.

**Installed copy (Setup.exe).** `packaging/build.ps1` stages Windows' embeddable Python 3.12 (packages from `requirements-lock.txt`, the versions tested on the dev computer), the app, `frontend/dist`, the Remotion source, Node and FFmpeg (pinned with sha256 in `packaging/tools.json`), runs `--self-test`, compiles `packaging/installer.iss` (Inno Setup, per-user, no admin), then installs silently into `build/`, self-tests and uninstalls. An `INSTALLED` file next to `app/` switches `app/paths.py`: data, `settings.env`, logs and the prepared Remotion copy (`remotion.sync_source`) go to `%LOCALAPPDATA%\AI Reel Maker` (`AIREEL_HOME` overrides), port 5050 on 127.0.0.1. `launcher.pyw` (run by `pythonw.exe` from the Start menu) puts bundled ffmpeg/node first on PATH, hides child console windows (`utils/no_console.py`), logs to `logs/app.log`, and stops the app when its Edge/Chrome `--app` window (own profile) closes; `--stop` is the Stop shortcut. Bump `app/version.py` for a release.

## Gotchas

- **Use `qwen3-vl:*-instruct` tags.** The bare `qwen3-vl:2b/4b/8b/30b/latest` tags are thinking models. They ignore `think: false`, spend the whole reply budget on reasoning, and return empty content, so every scene silently falls back to motion scoring. `health()` warns about this.
- **Use `qwen3:4b-instruct-2507-q4_K_M` for 4B text.** The bare `qwen3:4b` tag now points to the thinking-only 2507 build; with `think: false` and no schema it writes its reasoning into the reply.
- `qwen3:4b` pretty-prints JSON (about 42–46 reply tokens per transcript segment), so `_TEXT_TOKENS_PER_SEGMENT` is 48. Not re-measured on the instruct tag; a reply that hits the limit is split and retried. On CPU, reply tokens dominate model time (about 95% for transcript scoring). A compact-key / 0–10 format was tested and was **not** adopted: it was about 20% faster but slightly worse against a `qwen3:14b` reference.
- Tests stub `requests.Session.request` and use fake clients whose `chat()` takes the long-key reply format (`importance`, `visual_importance`, …). Keep reply parsing compatible with them. An autouse fixture in the Ollama tests stubs out the global `time.sleep`.
- **Claude CLI: never `--bare`.** It only accepts an API key and ignores the subscription login. The engine relies on `--restricted` + `--tools ""` + `--strict-mcp-config` and runs from the job's `brief/` folder so no project CLAUDE.md is read.
- FFmpeg 9 (gyan.dev build) segfaults on `drawtext`; burned text goes through ASS subtitles (`spec_ass`) or Remotion.
- npm's allow-scripts policy skips esbuild's postinstall in `remotion/` and `frontend/`; the platform binary still comes from its optional dependency.
- Line endings: `core.autocrlf=true`. HEAD stores LF and working copies may be CRLF; don't mix both in one file.

See `docs/performance-and-gpu-options.md` for CPU performance measurements, external GPU / cloud API options and the planned backend integration.
