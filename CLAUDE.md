# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A local-only app that turns a long video into a short highlight. Flask + Socket.IO backend (`app/`), React + Vite frontend (`frontend/`), FFmpeg for all media work, faster-whisper for speech, and Ollama (vision + text models) for scoring. No cloud AI: the only network calls go to the configured Ollama URL(s).

## Commands

```bash
pip install -r requirements.txt
python run.py                                  # API + built UI on APP_PORT (default 5000); one copy at a time
start.bat / stop.bat                           # Windows double-click start (builds UI if missing, opens browser) / stop
python scripts/stop_app.py                     # stop the running app and its FFmpeg children (data/app.pid)
cd frontend && npm install && npm run build    # UI served from frontend/dist by Flask
cd frontend && npm run dev                     # UI on 5173, proxies /api and /socket.io to 5000
cd frontend && npx tsc --noEmit -p .           # frontend type check (there is no lint setup)

python -m pytest -q                            # all tests (pytest.ini sets testpaths and pythonpath)
python -m pytest tests/test_performance.py -q
python -m pytest tests/test_ai_reliability.py::test_predict_budget_grows_with_batch_and_respects_context

python scripts/check_system.py                 # FFmpeg / Whisper / Ollama readiness
python scripts/pipeline_benchmark.py VIDEO --runs 3   # per-stage timings + model token usage
```

Two tests fail on a clean checkout and are not regressions: `test_api.py::test_sample_video_endpoint` (needs `samples/sample.mp4`, create it with `scripts/generate_sample.py`) and `test_candidate_fallback.py::test_generates_scene_windows_when_transcript_is_empty`.

The user runs the app natively on Windows (CPU-only, ~16 GB RAM, Ollama installed on the host). Docker/Compose files exist but are not the user's current setup.

## Architecture

**Request → job → worker.** Routes (`app/routes/`) only create and inspect jobs. `JobManager` (`app/services/job_manager.py`) stores jobs in SQLite (`data/app.db`) and files under `data/jobs/<id>/`. A single daemon thread (`app/workers/worker.py`) polls for `queued` jobs and runs either analysis or render. Progress and logs go out over Socket.IO (`job_progress`, `job_log`, …) and are appended to `job.log`. Jobs left mid-run are re-queued at startup; their attempt time counts up to the last heartbeat (`attempt_seen_at`, written every 15 s), and an interrupted analysis waits up to 3 minutes for Ollama (`_wait_for_ollama`) before falling back.

**Pause, crashes and power cuts.** `POST /jobs/<id>/pause` stops a run like a cancel (via the same cancel event), but the worker ends it as `paused` (`JobManager.take_pause_request`); paused jobs are never re-queued at startup, and `resume` re-queues them like `retry`. Every persistent JSON write goes through `app/utils/atomic.py` (temp file + fsync + rename); media is written under a temporary name (`part_path`, or `encoding/` for render clips) and renamed when complete. Slow steps save progress as they go and delete it when the step finishes: `transcript.partial.json` (Whisper resumes from the last saved segment), `segment_scores.partial.json` (keyed by a transcript fingerprint), `visual_analysis.partial.json` (keyed by the vision focus). Render clips are reused across runs when the fingerprint of their FFmpeg command (plus burned subtitle text) in `tmp_render/<label>/clips_done.json` still matches.

**Analysis pipeline** (`app/analysis/pipeline.py`, `VideoAnalyzer`): metadata → scenes (PySceneDetect) → audio → transcript (Whisper) → silence → frames (+ picture quality and loudness from `signals.py`, cached as `scene_quality.json` / `audio_energy.json`) → transcript AI → visual AI (only on `shortlist_scenes` unless `vision_scope=all`) → candidates (incl. sentence-complete joins, focus matching via `semantic.py`) → repetition removal (word-based, plus calibrated Ollama embeddings when `ollama_embed_model` is installed) → planning (`ClipOptimizer`). Transcript scoring must stay before visual analysis: it feeds the shortlist. Without speech (`enable_whisper` off, or `HighlightConfig.use_speech=False` from the Create page's "Visuals and sound only"), transcription and speech scoring are skipped without overwriting cached speech results, and the shortlist ranks scenes by a quick picture/motion/sound/quality signal. `app/analysis/image_match.py` adds optional SigLIP picture matching (ONNX, `Xenova/siglip-base-patch16-224`, full precision, downloaded from Settings; CPU by default, CUDA/DirectML when an onnxruntime GPU build is installed): it ranks scenes, marks lookalikes, matches the focus text to pictures, and improves quick scores for scenes the vision model skipped. It never overrides a vision-model score. `analyze_sources` handles one or many source videos. With several videos, each is analyzed in `job/work/<source id>/` and the candidates are merged before planning.

The `Connection` priority guides visual scoring toward affectionate gestures and meaningful interaction; the topic priorities (`people`, `scenery`, `fun`, `pets`, `music`, `sports`) work the same way. Each has weights in `scorer.PRIORITY_EMPHASIS`, a vision-prompt hint (`prompts.PRIORITY_VISUAL_HINTS`) and a SigLIP picture description (`prompts.PRIORITY_PICTURE_TEXT`). Styles have weights in `scorer.STYLE_EMPHASIS`, newer ones a transcript-prompt hint, and clip pacing in `sequence_limits.desired_auto_length`. Where a style and the chosen priorities weight the same signal, each counts half; with `auto`/`custom` style the priority weights apply unchanged. Connection quick presets set a 30–60s highlight or 10–20s short-moment target, a soft fade, natural-sound ranking, and suitable per-clip limits; each remains editable. "What to leave out" (`HighlightConfig.avoid`, `avoid_custom`, `avoid_mode`) lives in `app/analysis/avoid.py`: detectors store `avoid_match` on each candidate (transcript phrases, silence, picture quality, SigLIP contrast margins calibrated on real footage, an optional vision-model `avoid` score, embeddings for the user's words); `apply` ranks matches lower or removes them at planning time and in `plan_from_cache`, falling back to ranking lower if everything would be removed. Choosing picture or custom items changes the vision prompt, so cached visual scores are redone. Audio focus changes candidate ranking using the cached loudness curve and transcript coverage, never replaces or filters source audio. Fade transitions apply a brief fade to both picture and sound.

**Prompt mode** (`HighlightConfig.mode="prompt"`, "Describe it" on the Create page; manual mode is unchanged). `app/ai/intent.py` turns the description into a settings patch plus `PromptRequirements` (keep / remove / moments / visual_cues / audio_cues): regex rules read lengths, times, shape, captions and shorts (they win over the model), the text model reads the meaning (`INTENT_SCHEMA`), and every value is validated through `HighlightConfig` (`POST /api/prompt/interpret`, shown as an editable preview). Prompt-mode analysis adds: a `caption` per AI-scored scene (vision reply, `VISION_CAPTION_TOKENS`; AI scores without a caption are redone, AI scores are never overwritten by fallbacks), CLAP sound labels (`app/analysis/audio_events.py`, features in `clap_features.py` match HF's ClapFeatureExtractor; 5 s windows on a temporary 48 kHz copy; `sound_events.json` + `sound_vectors.npy`, so new wanted sounds re-match without re-reading audio; model downloaded from Settings via the shared `app/ai/onnx_models.HubModel`, like SigLIP), prompt-matching scenes added to the vision shortlist, `analysis_depth="best"` = every scene. `use_visuals` / `use_speech` are the per-job video/audio analysis switches (not both off). After repeat removal, `content_index.json` (captions + sounds per source) and the AI editor (`app/analysis/director.py`) pick candidates **by alias id only** (never times), with role and reason; long videos are read in parts then a final pick; the plan is cached in `director_plan.json` by a key of its inputs. `apply_director` makes picks a strong preference for `ClipOptimizer` (which still owns length, shorts, must-include/exclude, overlaps; picks skip the low-value/novelty filters; `order_mode="ai"` follows the editor's story order) and is applied in `plan_from_cache` too. "Ask AI to change" (`POST /jobs/<id>/refine`) appends to `refine_notes` and queues the job with `analysis_status="refining"`; the worker then runs `VideoAnalyzer.refine` (editor + planning from cache only). The editor uses role `"director"` in `role_options` (`ollama_director_num_ctx`, reloads the text model once) and optional `think` (`director_think`, retried without on errors). No Ollama: rules-only patch, the description becomes the focus, planning from scores.

**Stage cache.** Each stage writes a JSON file in the job folder (`scenes.json`, `transcript.json`, `visual_analysis.json`, `segment_scores.json`, …) and `load_cache` feeds them back, so re-planning and retries skip finished stages. Changing the crop clears the cache. AI scores are tagged by `app/analysis/score_source.py`: fallback scores with a retryable reason are redone when the model is available again, and untagged entries from older versions are kept. Cached AI scores are **not** invalidated when the style, custom focus or model changes; visual scores are refreshed when the set of priorities with a vision-prompt hint changes (stored in `visual_connection_focus.json`; older `true`/`false` values mean Connection on/off).

**Degraded modes are a feature.** Every AI step has a deterministic fallback: motion scoring for frames, heuristics for transcript segments. Ollama being down, a model missing, a reply cut off or malformed must never fail the job. Keep that property when touching `visual.py` / `pipeline.py`.

**Ollama client** (`app/ai/ollama.py`, shared instance from `services/ollama_runtime.get_ollama_client`):
- `role_options(role)` gives `num_ctx` (+ `num_thread` only when Ollama runs on this machine). Warm-up, probes and real calls must share it, because Ollama reloads a model when these options change.
- Batched JSON replies use `predict_budget`. A reply that hits the limit raises `OllamaTruncatedError`, and callers split the batch in half and retry.
- Batches are sized to fit the context window: `plan_text_batches` (transcript, token estimate) and `fitting_vision_batch` (vision; about 1,100 prompt tokens per image regardless of resolution, because Ollama upscales Qwen3-VL frames).
- Connection fallback: Docker host aliases, plus optional `OLLAMA_FALLBACK_URL`. The client returns to the configured URL when it answers again (checked at most once a minute). Optional `OLLAMA_API_KEY` is sent as a Bearer token and is filtered out of `GET /api/settings`.
- `usage_snapshot()` keeps per-thread token and time totals. The pipeline logs them per stage, and logs stage timings at the end.

**Model choice.** `app/services/hardware.py` detects CPU (name, performance/efficiency cores, AVX), every graphics adapter (NVIDIA via `nvidia-smi`, AMD/Intel VRAM on Windows from the display-class registry, ROCm VRAM, built-in vs separate), battery, and whether Whisper can use CUDA (`ctranslate2`, not torch). An AMD/Intel card counts for inference only once Ollama was seen running a model on it (`gpu_confirmed` setting). `app/services/model_catalog.py` recommends models from VRAM/RAM/CPU and the goal `ai_goal` (`quality`/`balanced`/`fast`); RAM is compared as its label size (`nominal_ram_gb`: 15.8 GB counts as 16), and vision batch and context come from the shared `app/ai/context_fit.py` sums, so recommended values are what jobs actually use. `app/services/ai_profile.py` applies the recommendation in **auto** mode when the hardware fingerprint changes. Bump `RECOMMENDATION_VERSION` whenever recommendations change, so existing auto-mode installs pick them up once. Custom mode is never overwritten. In auto mode, a managed setting edited by hand is **pinned** (`ai_auto_pinned`) instead of turning auto off; a recommended Ollama model that is not installed is held (`hw_auto_held`) until it is downloaded; Ollama-host settings are left alone when Ollama is on another computer. `app/services/auto_tune.py` backs the Settings switch "Automatically optimize for my system": goal, pins, review of changes with reasons, undo snapshot (`auto_tune_previous`), and per-run speed history (`perf_history`) that only produces suggestions, never automatic changes. `app/services/calibration.py` ("Measure this computer", `perf_profile`) measures real model speed and turns it into time estimates and suggestions only. It manages exactly `ai_profile.APPLIED_FIELDS`, and other settings are never touched.

**Run plan.** `app/services/run_plan.py` decides per job, from live free memory and load, whether models are loaded one at a time (Whisper and SigLIP released after use, other Ollama models unloaded before visual AI with `keep_alive: 0`) and Whisper precision on small cards. Never saved, never swaps models. When a model runs out of memory, visual and transcript scoring free the other models and retry in halves, then fall back with the retryable `AI_FAILED` reason.

**Settings precedence.** `.env` / environment → `Settings` (`app/config.py`). Values saved from the UI go into the SQLite `settings` table and are overlaid by `effective_settings()`; only keys in `EDITABLE` (`app/routes/settings.py`) can be saved. Editing a managed key in auto mode pins it (see Model choice).

**Video** (`app/video/`): `VideoProcessor` builds FFmpeg argv lists (never shell strings; paths go through `safe_path_argument`). `FFmpegRunner` executes them, can run several at once (parallel frame extraction), and `cancel()` kills all of them. `Renderer` cuts and concatenates the clip plan, with optional subtitles, 9:16 output and hardware encoders. Each clip is cut on its own and starts at 0, so burned subtitles are written per clip (`captions.py`, plain SRT or styled ASS) through the `clip_subtitles` callback. `reframe.py` centres 9:16/1:1/4:5 crops on faces per clip.

**Render** (`_run_render` in `worker.py`): kept clips with their times exactly as saved on Review (no longest-clip clamp: the planner already fits planned clips, so a longer clip was made longer on purpose; clips with end ≤ start are skipped with a warning) → optional tighten (`analysis/tighten.py`, pieces marked `join_previous`) → `render_groups`: one `highlight.*`, or `short_NN.*` per short when `HighlightConfig.shorts_count` ≥ 2 (clips carry `short_index`, planned by `ClipOptimizer.select_shorts`). Output rows and stale files are replaced only after every video is made. Routes that serve output take `?short=N` (`services/outputs.py`). Per clip the renderer can add even loudness (`audio_mix.py`: measure, then `volume` + `alimiter`) and picture extras (`overlays.py`: punch-in, logo via `movie=`, progress bar via `color` + `overlay`, all inside the clip's `-vf` graph). Background music is mixed into each finished video afterwards (`add_music` in `worker.py`); translated subtitles come from `services/translate.py`. `analysis/speakers.py` tells voices apart on demand (numpy MFCC + pitch voice prints, agglomerative clustering with silhouette and a separation check; cached in `speakers.json`, used by `plan_from_cache` when `focus_speaker` is set, filtered before repeat removal). `services/watch_folder.py` runs a polling thread (started with the worker) that creates `auto_render` jobs. The editor export (`services/editor_export.py`) uses the same clips and tightening so its timelines match the video.

## Where to look

- New pipeline stage or cache file: `app/analysis/pipeline.py` and `load_cache` in `app/workers/worker.py`.
- AI prompts / reply parsing: `app/ai/prompts.py`, `analyze_scenes_visual` in `app/analysis/visual.py`.
- Clip selection and length: `app/analysis/optimizer.py`, `app/analysis/sequence_limits.py`; candidate windows in `candidates.py` / `boundaries.py`.
- New setting: `app/config.py` → `EDITABLE` in `app/routes/settings.py` → `frontend/src/pages/Settings.tsx` + `frontend/src/types/index.ts` (+ `ai_profile.APPLIED_FIELDS` if model-related).
- Render output: `app/video/renderer.py`, `app/video/quality.py` (canvas, frame rate, encoder args).
- Frontend: pages in `frontend/src/pages/` (routes in `App.tsx`), API calls in `services/api.ts`, UI strings in `i18n/en.json`, Help page content in `docs/content.ts` (checked by `scripts/check-docs.mjs`).

## Gotchas

- **Use `qwen3-vl:*-instruct` tags.** The bare `qwen3-vl:2b/4b/8b/30b/latest` tags are thinking models. They ignore `think: false`, spend the whole reply budget on reasoning, and return empty content, so every scene silently falls back to motion scoring. `health()` warns about this.
- **Use `qwen3:4b-instruct-2507-q4_K_M` for 4B text.** The bare `qwen3:4b` tag now points to the thinking-only 2507 build; with `think: false` and no schema it writes its reasoning into the reply.
- `qwen3:4b` pretty-prints JSON (about 42–46 reply tokens per transcript segment), so `_TEXT_TOKENS_PER_SEGMENT` is 48. Not re-measured on the instruct tag; a reply that hits the limit is split and retried. On CPU, reply tokens dominate model time (about 95% for transcript scoring). A compact-key / 0–10 format was tested and was **not** adopted: it was about 20% faster but slightly worse against a `qwen3:14b` reference.
- Tests stub `requests.Session.request` and use fake clients whose `chat()` takes the long-key reply format (`importance`, `visual_importance`, …). Keep reply parsing compatible with them. An autouse fixture in the Ollama tests stubs out the global `time.sleep`.
- Line endings: `core.autocrlf=true`. HEAD stores LF and working copies may be CRLF; don't mix both in one file.

See `docs/performance-and-gpu-options.md` for CPU performance measurements, external GPU / cloud API options and the planned backend integration.
